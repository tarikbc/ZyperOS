File Transfer, round two

my five asks and his two notes, as choices. A transfer that keeps going in the background, a safe way to stop it, games while files move, pixel-art icons on every folder, a time left for the uploads, a check for free space, and a Settings page with an update over the USB cable. Pick one option in each section. Add a note to change anything.

What I found first

  1. Why .media is everywhere. A new card gets an empty .media in each of its 41 system folders (mk/payload.sh), and every System Update puts them back (its .card list). Box Art and the Scraper also make one before each try, so a cover that never comes leaves an empty folder. The ones in Music hold real album covers. The fix: make .media only when a cover lands, remove the empty ones, and hide dot folders in the page.
  2. Why Atomiswave had no bar. The page took its colors from the shelf's list, and the shelf hides a system with no games. BGM is not a system, so it had nothing. Every option below fixes both.
  3. What the page can get from GitHub. It can read the list of releases (api.github.com allows a web page to). It cannot read the release files: github.com and release-assets.githubusercontent.com send no CORS header, so the browser blocks the bytes. Section 9 shows the two ways around this.
  4. Games and transfers. The transfer server runs in the launcher's loop. A game takes that loop, and a port even restarts the launcher. So files stop moving during a game, and a browser gives up after 20 seconds of silence. Games must wait.
  5. Free space. Today the handheld refuses a file that does not fit, one file at a time, after the files before it went. The page never adds up a batch first.
