ZyperOS Scraper Lab

One MENU row, Scraper, in place of Box Art, ScreenScraper and SteamGridDB: the three sources and their links, the run that fetches missing box art, and the video snaps a game's cover turns into after 3 seconds on the shelf. Six decisions; every screen is in the launcher's own units and colors, Beard and Salt & Pepper.

Connecting…

Kept in every option.
  • MENU > Scraper sits where Box Art is now, and its value says what is missing: "142 missing", or "complete". A console's own menu keeps its Box Art row: the same run for that console alone.
  • The order is fixed: ScreenScraper when linked (box art, year, genre, synopsis, video snaps), then libretro (no account), then SteamGridDB when linked (box art for what the other two lack). Replace Box Art (X on a game) asks the same sources in the same order and keeps the old cover when nothing is found.
  • Linking is checked once against the service. ScreenScraper has no token: its API signs every request with the password, so the device keeps the user and the password, as it does today, in the device's settings and never in a log. SteamGridDB keeps its key, shown only as ••••1a2b. The key can still be pasted on the File Transfer page.
  • Video snaps come from ScreenScraper only (its small "video-normalized" file, about 1 to 3 MB a game, beside the cover in the console's .media folder), so they need ScreenScraper linked. On the shelf they are decoded by MP4's video path, and only while one is on screen: the shelf must still scroll at about 59 fps, input must answer as fast as today, and the CPU must go back to rest when the snap stops. Measured on the Pixel 2 before it ships. Any press, or a menu opening, puts the cover back at once.
