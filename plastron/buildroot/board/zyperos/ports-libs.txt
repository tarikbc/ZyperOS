# The libraries PortMaster's ports and their runtimes load from the system
# rather than from their own folders: each one's soname, the package that
# puts it in the image (by its name in the image's package list,
# board/px2/third-party-packages.md), the option that asks for that package
# ("-" where another package's option brings it in), and what loads it.
#
# scripts/ports-libs.sh checks a built root has each one, and
# scripts/release.sh runs it over the Pixel 2's image. ZyperOS's
# make check-portlibs checks each option is set and each package listed for
# every device whose ZyperOS runs ports (HAS_PORTS=1 in its
# sd/<device>/device.sh): the Pixel 2 only, so far.
#
# The Westonpack lines are what PortMaster's weston_pkg_0.2.squashfs
# (PortMaster-New's release 2025-07-24_0745, md5
# 0a761c28877625861d9c9c4326664428, its version.txt wp_version=271) needs
# beyond its own lib_aarch64: the NEEDED entries of its weston (wp_weston),
# the modules a port's westonwrap.sh line loads (DRM backend, GL renderer,
# kiosk shell, Xwayland), seatd, Xwayland, xkbcomp and weston-keyboard, each
# looked up in the folders westonwrap.sh puts first (Crusty's crusty_gbm,
# lib_aarch64, mesa_x11_stub), and the ones its start looks for by name
# (tools/findlib, Crusty). glibc's own are left out.
#
# libudev.so.1 among them: the runtime carries a stand-in libudev of
# Crusty's, but not in a folder its westonwrap.sh puts on the library path
# (LD_LIBRARY_PATH=:/tmp/weston/lib_aarch64: when weston starts), so weston
# takes it from the system, and on 1.1.0, with no udev, stopped there
# ("./wp_weston: error while loading shared libraries: libudev.so.1").
# libudev-zero is that library without udev.
#
# board/zyperos/ports-cmds.txt is the same for the commands the ports'
# scripts run, and scripts/ports-libs.sh checks both.
#
# soname            package      option                  loaded by
